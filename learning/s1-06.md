# S1-06 · [Python] Client BODACC (5 h)
Liste : S1 — Repo, Terraform, ingestion BODACC · Échéance : 2026-11-01 · Étiquettes : orange, violet · [Carte Trello](https://trello.com/c/Cdgddvop)

## Objectif
Écrire `packages/bodacc-client`, une lib Python testée qui renvoie toutes les annonces d'une journée via `BodaccClient.fetch_day(date) -> Iterator[dict]` (export JSONL en streaming, retries exponentiels, timeout, modèle Pydantic) — Pourquoi ça compte dans le projet : la Lambda d'ingestion (S1-07) n'est qu'une coquille autour de ce client ; tout ce qui arrive dans `raw` passe par lui, donc ses erreurs (annonces perdues, doublons, 429 mal gérée) deviennent des trous ou des doublons dans la table `events`.

## Prérequis
### httpx : client HTTP synchrone et streaming
`httpx.Client` ≈ une instance `axios.create({ baseURL, timeout, headers })` : il garde la connexion ouverte entre les appels et se ferme avec `with httpx.Client(...) as c:` (≈ `try/finally` qui appelle `close()`). `c.get(url, params={...})` encode la query string à ta place. Pour un gros corps, `with c.stream("GET", url, params=...) as r:` puis `for line in r.iter_lines():` lit ligne par ligne sans charger les 59 Mo en mémoire (≈ un `ReadableStream` lu par morceaux). `httpx.Timeout(60.0, connect=5.0)` règle les délais ; par défaut c'est 5 s, trop court pour l'export.
Doc : https://www.python-httpx.org/advanced/clients/ · https://www.python-httpx.org/quickstart/#streaming-responses · https://www.python-httpx.org/advanced/timeouts/
Exercice 5 min : `uv run --with httpx python -c "import httpx; r = httpx.get('https://httpbin.org/get', params={'q': 'a b'}); print(r.status_code, r.json()['url'])"` → `200 https://httpbin.org/get?q=a+b`. Observer l'encodage de l'espace.

### Générateurs et `Iterator`
Une fonction qui contient `yield` est un générateur : l'appeler ne fait **rien**, ça renvoie un itérateur ; le corps s'exécute au premier `next()` / premier tour de `for` (≈ `function*` en JS). Conséquences : les erreurs réseau sortent pendant l'itération, pas à l'appel ; un `with` dans le générateur reste ouvert tant que l'appelant n'a pas fini d'itérer. Typage : `from collections.abc import Iterator` puis `def f() -> Iterator[dict]:`. `itertools.islice(gen, 3)` ne consomme que 3 éléments.
Doc : https://docs.python.org/3/howto/functional.html#generators · https://docs.python.org/3/library/itertools.html#itertools.islice
Exercice 5 min : écrire dans `python3` un générateur `compte()` qui affiche `"début"` puis `yield 1` et `yield 2`. Appeler `g = compte()` : rien ne s'affiche. `next(g)` : `début` puis `1`. Expliquer pourquoi.

### Pydantic v2 : valider et transformer une annonce
`class Annonce(BaseModel)` ≈ un schéma `zod` qui est aussi une classe : `Annonce.model_validate(dict)` ≈ `schema.parse(obj)`, lève `ValidationError` si un champ ne colle pas. `model_config = ConfigDict(extra="ignore")` ignore les champs non déclarés. `@field_validator("listepersonnes", mode="before")` ≈ un `z.preprocess` : transforme la valeur brute avant validation, c'est là qu'on fait le second `json.loads` des champs BODACC sérialisés. `@computed_field` expose une valeur calculée (ex. `siren`).
Doc : https://docs.pydantic.dev/latest/concepts/models/ · https://docs.pydantic.dev/latest/concepts/validators/#field-validators · https://docs.pydantic.dev/latest/concepts/fields/#the-computed_field-decorator
Exercice 5 min : `uv run --with pydantic python -c "from pydantic import BaseModel; from datetime import date; M = type('M', (BaseModel,), {'__annotations__': {'d': date}}); print(repr(M.model_validate({'d': '2026-10-20'}).d))"` → `datetime.date(2026, 10, 20)`. La chaîne est convertie en `date`.

### pytest, respx, fixtures
Un test = une fonction `test_*` avec `assert`. Une fixture `@pytest.fixture` ≈ un `beforeEach` qui **injecte** sa valeur dans les tests qui la nomment en paramètre ; placée dans `tests/conftest.py`, elle est visible par tous les tests du dossier. `respx` intercepte les requêtes `httpx` (≈ `msw` / `nock`) : `respx_mock.get(url).mock(return_value=httpx.Response(200, text=...))`, ou `side_effect=[r1, r2]` pour enchaîner des réponses (429 puis 200). Les « réponses enregistrées » de la carte = un vrai extrait de l'export sauvegardé dans `tests/fixtures/`.
Doc : https://docs.pytest.org/en/stable/how-to/fixtures.html · https://lundberg.github.io/respx/guide/ · https://lundberg.github.io/respx/api/#side-effect
Exercice 5 min : lire la page « Guide » de respx jusqu'à « Pattern matching ». Noter comment une route matche les `params` de la query string et ce qui se passe si une requête ne matche aucune route (`assert_all_mocked`).

### Retries exponentiels et `Retry-After`
Réessayer une requête qui a échoué pour une raison transitoire (429, 502, 503, 504, timeout), avec une attente qui double à chaque tentative (1 s, 2 s, 4 s…) plafonnée, et un nombre d'essais borné. Si le serveur envoie `Retry-After: <secondes>`, il prime. Les erreurs non transitoires (400, 404) ne se réessaient pas. Pour tester sans attendre, la fonction d'attente est **injectée** (`sleep=time.sleep` par défaut, une fausse fonction qui enregistre les durées en test) : c'est de l'injection de dépendance, comme passer un `fetch` mocké.
Doc : https://docs.python.org/3/library/time.html#time.sleep · https://developer.mozilla.org/fr/docs/Web/HTTP/Headers/Retry-After
Exercice 5 min : calculer à la main les attentes pour `base=1`, `factor=2`, `max_delay=30`, 6 tentatives. Quelle durée totale maximum avant l'échec final ? Est-ce compatible avec le timeout d'une Lambda à 5 min (S1-07) ?

## Pièges courants (dev TS → Python)
1. Un générateur ne s'exécute pas à l'appel : `fetch_day(d)` seul ne fait aucune requête et ne lève aucune erreur. Les tests doivent itérer (`list(...)`, `islice`).
2. `with client.stream(...)` hors du générateur ferme la réponse avant le premier `yield` : `httpx.StreamClosed`.
3. Timeout `httpx` par défaut = 5 s : l'export d'une journée prend ≈ 5 s, il coupe aléatoirement. `Timeout(60, connect=5)`.
4. `r.json()` sur l'export échoue : le corps est du JSONL malgré `content-type: application/json`.
5. Retry après un `yield` = doublons. Réessayer seulement l'ouverture du flux ; au-delà, échouer et laisser la Lambda rejouer la date.
6. `time.sleep` en dur rend les tests lents : l'injecter (`sleep=time.sleep` en paramètre).
7. Pydantic v2 : `model_validate` / `model_dump`, pas `parse_obj` / `dict()` (API v1, encore visible dans de vieux tutos).
8. `uv add` sans `--package` ajoute la dépendance à la racine, pas au membre : le zip Lambda de S1-07 n'aurait pas `httpx`.
9. Arguments par défaut mutables (`def f(x=[])`) partagés entre appels : `None` par défaut puis créer dans le corps.
