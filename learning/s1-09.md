# S1-09 · Documentation et AGENTS.md (1 h)
Liste : S1 — Repo, Terraform, ingestion BODACC · Échéance : 2026-11-01 · Étiquettes : aucune · [Carte Trello](https://trello.com/c/HX60877S)

## Objectif
Qu'un inconnu (humain ou agent de code) puisse cloner le dépôt, comprendre l'architecture en une minute et aller jusqu'à `make up` sans aide, et livrer la preuve de fin de semaine 1 — Pourquoi ça compte dans le projet : à partir de S2 le dépôt grossit (PySpark, Step Functions, agent) ; un README qui ment ou un agent qui ignore les règles (numéro de compte, état Terraform, commandes AWS en écriture) coûte plus cher que la doc elle-même.

## Prérequis
### README orienté « premier lancement »
Un README de dépôt d'infrastructure répond dans l'ordre à : c'est quoi (architecture en quelques lignes), il me faut quoi (outils, versions, compte AWS), comment je démarre de zéro (étapes numérotées, dans l'ordre réel des dépendances), quelles commandes au quotidien. Le détail vit dans les README des dossiers (`infra/README.md`, `lambdas/ingest_bodacc/README.md`) : le README racine les relie, il ne les recopie pas. ≈ le README d'un repo Next.js : `pnpm i`, `.env.local`, `pnpm dev`, mais avec un compte AWS à préparer avant.
Doc : https://www.makeareadme.com/
Exercice 5 min : lire `README.md` comme si tu découvrais le projet et noter la première commande qui échouerait sur une machine vierge (indice : quels fichiers gitignorés faut-il créer, et dans quel ordre par rapport au bucket d'état et aux zips de Lambda ?).

### AGENTS.md et CLAUDE.md
`AGENTS.md` est un fichier Markdown à la racine qui donne aux agents de code (Claude Code, Codex, Cursor…) ce qu'un nouveau développeur apprendrait en revue de code : structure, commandes de vérification, conventions, interdits. Claude Code lit `CLAUDE.md` ; un `CLAUDE.md` d'une ligne `@AGENTS.md` importe le fichier commun, sans doublon. Ce n'est pas de la doc pour humains : des règles courtes, impératives, vérifiables.
Doc : https://agents.md/ · https://docs.anthropic.com/en/docs/claude-code/memory
Exercice 5 min : lister trois choses qu'un agent pourrait faire de travers dans ce dépôt sans qu'aucun test ne le détecte (ex. écrire le numéro de compte dans un fichier commité).

### Tester une doc : le parcours « inconnu »
Une doc se teste comme du code : cloner dans un dossier vide, suivre le README à la lettre, sans rien deviner, et noter chaque endroit où il faut savoir quelque chose qui n'est pas écrit. Un relecteur sans contexte (un collègue, ou un agent qui ne lit que le dépôt) trouve ce que l'auteur ne voit plus.
Doc : https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes
Exercice 5 min : `git clone` du dépôt dans un dossier temporaire puis `ls -a` : quels fichiers de config présents sur ton poste (`local.tfvars`, `backend.hcl`, `local.auto.tfvars`) n'y sont pas, et le README dit-il comment les créer ?

### Livrable : preuve S3 et graphe CloudWatch
`aws s3 ls s3://<raw>/bodacc/` liste les partitions `date=` ; `aws cloudwatch get-metric-widget-image` rend un graphe de métrique en PNG à partir d'une définition JSON (la même que celle d'un widget de tableau de bord), sans passer par la console.
Doc : https://docs.aws.amazon.com/AmazonCloudWatch/latest/APIReference/API_GetMetricWidgetImage.html
Exercice 5 min : `aws cloudwatch get-metric-statistics --namespace AWS/Lambda --metric-name Invocations --dimensions Name=FunctionName,Value=data-platform-dev-ingest-bodacc --start-time 2026-10-25T00:00:00Z --end-time 2026-10-26T00:00:00Z --period 3600 --statistics Sum --profile data-platform --query 'Datapoints[].[Timestamp,Sum]' --output text` → repérer l'heure du rejeu de 19 jours.

## Question de compréhension
Un agent de code reçoit la consigne « ajoute une deuxième source de données » dans ce dépôt : quelles règles d'`AGENTS.md` l'empêchent de casser quelque chose que les tests ne verraient pas, et lesquelles ne peuvent pas être vérifiées automatiquement (donc reposent sur la relecture humaine) ?

- Réponse (donnée par le tuteur, à la demande de l'utilisateur) :
  1. Protègent l'ajout d'une source : procédure « Ajouter une Lambda » (entrée de `local.lambdas` → rôle minimal, log group, retries bornés et **alarme `Errors` hérités** ; une Lambda copiée n'aurait pas d'alarme, aucun test ne le verrait) ; pas d'ARN ni de compte en dur (`local.prefix`) ; écritures idempotentes `<source>/date=…/` + manifest en dernier (lisibles par S2 et `raw('<source>')`) ; affirmer après mesure sur une journée complète ; pas d'`apply` ni d'écriture AWS sans humain ; `make sync`, `make check`, `make plan` avant de rendre la main.
  2. Vérifiables automatiquement : tests et lint (`make check`), Terraform + tags (`make plan`), `uv.lock` (hook) ; automatisables mais pas encore faits : numéro de compte (hook pre-commit qui refuse 12 chiffres), préfixe de commit et pas de `Co-Authored-By` (hook `commit-msg`), pas d'écriture AWS (profil **lecture seule** pour l'agent : la règle portée par IAM, pas par le texte).
  3. Relecture humaine seulement : affirmer après mesure plutôt que de mémoire, idempotence réelle sur AWS (les tests utilisent de faux clients), pertinence du découpage et du moindre privilège, format du cours.
  4. Leçon : une règle d'`AGENTS.md` est une intention ; dès qu'elle peut devenir un hook ou une permission, elle doit le devenir ; le texte garde ce qui demande du jugement.
