# S1-07 · Lambda d'ingestion (4 h)
Liste : S1 — Repo, Terraform, ingestion BODACC · Échéance : 2026-11-01 · Étiquettes : orange · [Carte Trello](https://trello.com/c/61HS2012)

## Objectif
Déployer `lambdas/ingest_bodacc`, une Lambda Python qui reçoit une date (J-1 par défaut), lit la journée avec `BodaccClient.fetch_day`, écrit `s3://<raw>/bodacc/date=YYYY-MM-DD/part-0001.jsonl.gz` puis `_MANIFEST.json`, et peut être rejouée sans doublon — Pourquoi ça compte dans le projet : c'est le premier maillon exécuté chaque jour par Step Functions (S2) ; le job PySpark ne lira une partition que si son manifest existe, donc une Lambda non idempotente ou qui écrit le manifest trop tôt produit des trous ou des doublons dans la table `events`.

## Prérequis
### Handler Lambda Python
Le runtime appelle `module.fonction(event, context)` : `event` est un `dict` (le JSON reçu, pas une requête HTTP), `context` donne `aws_request_id` et `get_remaining_time_in_millis()`. La valeur renvoyée est sérialisée en JSON. ≈ un handler Lambda Node `export const handler = async (event, context) => …`, mais synchrone. Ce qui est au niveau module (imports, clients boto3) s'exécute une fois par conteneur (cold start) puis est réutilisé : y mettre les clients coûteux, pas l'état d'une invocation. Timeout par défaut : 3 s, à monter.
Doc : https://docs.aws.amazon.com/lambda/latest/dg/python-handler.html · https://docs.aws.amazon.com/lambda/latest/dg/python-context.html
Exercice 5 min : écrire dans `python3` une fonction `handler(event, context)` qui renvoie `{"date": event.get("date", "défaut")}`. L'appeler avec `handler({}, None)` puis `handler({"date": "2026-10-20"}, None)`. Pourquoi `event.get` plutôt que `event["date"]` ?

### Dates : `date`, `datetime`, fuseau `Europe/Paris`
`date` = jour sans heure ; `datetime` = instant. Un `datetime` sans `tzinfo` est « naïf » : il ne sait pas dans quel fuseau il est (≈ une chaîne ISO sans `Z`). Lambda tourne en UTC : à 00:30 à Paris il est encore la veille en UTC, donc « J-1 » calculé en UTC peut viser J-2. `datetime.now(ZoneInfo("Europe/Paris")).date() - timedelta(days=1)` donne la veille à Paris. `date.fromisoformat("2026-10-20")` parse une date d'event. Pour tester sans dépendre de l'horloge, injecter `now` (comme `sleep` dans le client).
Doc : https://docs.python.org/3/library/datetime.html#aware-and-naive-objects · https://docs.python.org/3/library/zoneinfo.html
Exercice 5 min : `uv run python -c "from datetime import datetime, timedelta; from zoneinfo import ZoneInfo; t = datetime(2026, 10, 24, 22, 30, tzinfo=ZoneInfo('UTC')); print(t.astimezone(ZoneInfo('Europe/Paris')).date() - timedelta(days=1), t.date() - timedelta(days=1))"` → deux dates différentes. Expliquer laquelle est « J-1 » pour un humain à Paris.

### `gzip`, `hashlib`, octets déterministes
`gzip.GzipFile(fileobj=f, mode="wb", mtime=0)` compresse ce qu'on y écrit ; sans `mtime=0`, l'heure courante est écrite dans l'en-tête et deux compressions du même contenu donnent des octets différents. `hashlib.sha256()` se nourrit par morceaux (`h.update(b)`) puis `h.hexdigest()` (≈ `crypto.createHash('sha256')` Node). Python distingue `str` et `bytes` : `json.dumps(...)` rend un `str`, il faut `.encode("utf-8")` avant d'écrire dans un fichier binaire.
Doc : https://docs.python.org/3/library/gzip.html#gzip.GzipFile · https://docs.python.org/3/library/hashlib.html · https://docs.python.org/3/library/tempfile.html
Exercice 5 min : compresser deux fois `b"bonjour"` avec `gzip.compress(b"bonjour")`, comparer les `sha256` ; recommencer avec `gzip.compress(b"bonjour", mtime=0)`. Noter quand les deux hash sont égaux.

### boto3 et moto
`boto3.client("s3")` ≈ `new S3Client({})` du SDK v3, mais synchrone et sans types natifs. `s3.upload_file(chemin, bucket, cle)` envoie un fichier en multipart si nécessaire ; `s3.put_object(Bucket=, Key=, Body=, ContentType=)` pour un petit objet. Les paramètres sont en `PascalCase`, comme l'API REST. `moto` intercepte boto3 en mémoire (≈ `aws-sdk-client-mock`) : `with mock_aws():` ou décorateur, puis on crée le bucket dans le test. Il faut de faux identifiants (`AWS_ACCESS_KEY_ID=testing`) et une région, sinon boto3 tente le vrai compte.
Doc : https://boto3.amazonaws.com/v1/documentation/api/latest/reference/services/s3/client/upload_file.html · https://docs.getmoto.org/en/latest/docs/getting_started.html
Exercice 5 min : lire « Getting Started » de moto jusqu'à « Example on usage » et repérer pourquoi la doc recommande une fixture `aws_credentials` avant toute création de client.

### Packaging Lambda : zip, layer ou image
Trois façons de livrer le code : un zip (≤ 50 Mo zippé en upload direct, 250 Mo décompressé), un zip + une layer (dépendances partagées entre fonctions), une image Docker (≤ 10 Go, ECR à gérer). Ici une seule fonction et ~15 Mo de dépendances : un zip suffit. Le piège : `pydantic-core` est compilé ; un `pip install` sur le Mac installe la roue macOS, qui plante sur Lambda (Linux). `uv pip install --target build/ --python-platform aarch64-manylinux2014 --only-binary :all:` télécharge les roues Linux ARM. `uv export --package ingest-bodacc --no-dev` produit la liste exacte des dépendances du membre, versions du lock.
Doc : https://docs.aws.amazon.com/lambda/latest/dg/python-package.html · https://docs.astral.sh/uv/guides/integration/aws-lambda/ · https://docs.astral.sh/uv/reference/cli/#uv-export
Exercice 5 min : `uv export --package bodacc-client --no-dev --no-hashes --frozen` → la liste de ce qu'un zip contenant le client embarquerait. Repérer le paquet compilé.

### Idempotence et marqueur de fin
Une opération est idempotente si l'exécuter deux fois laisse le même état qu'une fois (≈ `PUT` vs `POST`). S3 n'a pas de transaction multi-objets : on écrit d'abord la donnée, puis le manifest en dernier, qui sert de marqueur « partition complète ». Un lecteur qui ne voit pas de manifest ignore la partition ; un rejeu réécrit les mêmes clés (pas de clé avec horodatage ou UUID). Les buckets sont versionnés : l'ancienne version reste récupérable.
Doc : https://docs.aws.amazon.com/lambda/latest/dg/invocation-retries.html · https://docs.aws.amazon.com/AmazonS3/latest/userguide/Versioning.html
Exercice 5 min : lister ce qui ferait échouer « rejouer 2 fois = même résultat » si la clé était `part-<uuid>.jsonl.gz`, puis si le gzip gardait son `mtime`.

## Pièges courants (dev TS → Python)
1. Dépendances compilées installées depuis le Mac : `No module named 'pydantic_core._pydantic_core'` sur Lambda. Toujours `--python-platform` Linux de la bonne architecture.
2. `datetime.now()` naïf en UTC sur Lambda : « J-1 » décalé d'un jour entre minuit et 2 h à Paris.
3. `gzip` sans `mtime=0`, ou clé avec horodatage : deux rejeux donnent des octets ou des clés différents, l'idempotence est perdue sans que les tests unitaires le voient.
4. Manifest écrit avant le part, ou exception attrapée et avalée : un lecteur voit une partition « complète » vide ou tronquée.
5. Timeout par défaut à 3 s et `/tmp` à 512 Mo : la journée (~59 Mo brut) passe en mémoire, mais pas en 3 s.
6. moto sans faux identifiants : boto3 lit le profil `data-platform` et les tests touchent le vrai compte.
7. Log group créé implicitement par Lambda : hors Terraform, rétention infinie, survit à `make down`.
